# Задача 1. Sentry — мониторинг ошибок

## Зачем это нужно

Сейчас если у пользователя ломается сайт или бот, мы об этом не узнаём — пока пользователь не напишет в поддержку. Sentry решает это: каждая ошибка автоматически попадает в нашу панель, с детальным контекстом (что делал юзер, какой URL, какой stacktrace).

Код для интеграции уже написан и развёрнут. Не хватает только **DSN** — это уникальные адреса для отправки ошибок в твой Sentry-аккаунт. Без DSN сайт и бот работают как сейчас, просто молча игнорируют логирование.

## Шаг 1.1. Создание аккаунта Sentry

1. Открой **https://sentry.io/signup/**
2. Регистрируйся через **email** или **Google/GitHub** (как удобнее)
3. Когда спросят про план — выбери **Developer (Free)**. Бесплатного лимита (5 000 ошибок/мес) нам хватит на год вперёд.
4. Подтверди email если просят.

## Шаг 1.2. Создание организации

При первом входе Sentry попросит создать организацию.

- **Organization name**: `Symancy`
- **Organization slug** (автоматом): `symancy` — если занят, попробуй `symancy-ai`
- Остальные поля пропусти или оставь дефолтные.

Если у тебя уже есть какой-то аккаунт Sentry — создай отдельную организацию через меню в левом верхнем углу → **Switch organization** → **Create New Organization**.

## Шаг 1.3. Создание ПЕРВОГО проекта — Frontend (React)

1. В левом сайдбаре нажми **Projects** → **Create Project** (синяя кнопка справа сверху).
2. На странице "Create a New Project":
   - **Choose a platform**: в поиске введи `React` и выбери **React**
   - **Set your alert frequency**: выбери "**Alert me on every new issue**" (будет приходить уведомление при каждой новой ошибке)
   - **Project name**: `symancy-frontend`
   - **Team**: оставь дефолтную (`#symancy` или похожее)
3. Нажми **Create Project**.
4. После создания Sentry покажет страницу с инструкцией по интеграции. Тебя там интересует только одна строка — **DSN**. Она выглядит так:
   ```
   https://abc123def456@o111111.ingest.sentry.io/2222222
   ```
   **Скопируй её и сохрани в блокнот под названием `VITE_SENTRY_DSN`.**

Если случайно закрыл страницу — DSN можно найти позже:
**Settings** (шестерёнка слева внизу) → **Projects** → клик на `symancy-frontend` → **Client Keys (DSN)** в левом меню → секция **DSN → Public**.

## Шаг 1.4. Создание ВТОРОГО проекта — Backend (Node.js)

Повтори те же шаги, но:

1. **Projects** → **Create Project**
2. **Choose a platform**: введи `Node.js` и выбери **Node.js** (НЕ Express, не Next.js — именно "Node.js")
3. **Set your alert frequency**: "Alert me on every new issue"
4. **Project name**: `symancy-backend`
5. **Create Project**
6. Скопируй DSN. **Сохрани её под названием `SENTRY_DSN`** (без префикса `VITE_`).

## Шаг 1.5. Базовые настройки уведомлений (опционально)

Для каждого проекта стоит выключить мусорные уведомления:

1. Зайди в проект (`symancy-frontend` или `symancy-backend`).
2. **Settings** проекта (шестерёнка справа сверху, не путать с глобальными настройками) → **Alerts**.
3. Найди дефолтное правило **"Send a notification for new issues"** — оставь его включённым.
4. Если хочешь Telegram-уведомления:
   - **Settings** → **Integrations** → найди **Telegram** (если есть в интеграциях, или используй webhook)
   - Это можно пропустить и настроить позже.

## Шаг 1.6. Доступ для команды (опционально)

Если хочешь, чтобы Игорь тоже мог смотреть ошибки в Sentry:

1. **Settings** организации (шестерёнка слева внизу) → **Members**
2. **Invite Members**
3. Email Игоря: `maslennikov.ig@gmail.com`
4. Роль: **Admin** или **Manager**
5. **Send Invite**

## Что-то пошло не так (Sentry)

| Проблема | Решение |
|---|---|
| Email регистрации занят | Используй Google/GitHub-логин |
| Organization slug занят | Попробуй `symancy-ai`, `symancy-app`, `symancy-team` |
| Не вижу "Client Keys (DSN)" в проекте | Проверь, что ты в Settings *проекта* (внутри проекта), а не в Settings *организации* |
| DSN-строка пустая | Перейди на вкладку **Client Keys (DSN)** → нажми **Generate New Key**, если ничего нет |
| Сомневаешься какую платформу выбрать | Frontend = React, Backend = Node.js. Если выбрал не то — можно удалить проект и пересоздать |

# Задача 2. Telegram Payment Provider Token

## Зачем это нужно

Сейчас наш бот умеет принимать платежи в **Telegram Stars** (внутренняя валюта Telegram). Но многим российским пользователям удобнее платить **картой через ЮKassa прямо в Telegram** — это работает через специальный «провайдерский токен», который выдаёт сам Telegram (через @BotFather) после привязки магазина ЮKassa.

Без этого токена кнопка «Оплатить картой» в боте показывает пользователю ссылку на сайт. С токеном — оплата происходит сразу в Telegram, без перехода куда-либо.

**Важно**: у нас уже подключён ЮKassa-магазин для сайта (это другой набор ключей: shop_id и secret_key). Здесь нужен **отдельный токен** именно для Telegram-Bot-Payments.

## Что должно быть у тебя на руках

- Доступ к Telegram-аккаунту, под которым создан бот **@SymancyBot** (либо к аккаунту owner-а бота).
- Учётные данные ЮKassa-магазина (shop_id и secret_key) — спроси у Игоря, если нужны.

## Шаг 2.1. Открыть @BotFather

1. В Telegram найди **@BotFather** (синяя галочка, официальный бот Telegram для создания и настройки ботов).
2. Открой чат, отправь `/start` если ещё не делал.
3. Отправь команду `/mybots`.
4. Выбери из списка **Symancy** (или как бот называется в @BotFather — обычно отображается имя пользователя с `@`).

## Шаг 2.2. Войти в Payments

1. После выбора бота откроется меню. Нажми кнопку **Payments**.
2. Появится список доступных платёжных провайдеров. Ищи в списке **YooKassa** (он же может быть указан как **ЮKassa** или **YooMoney**).
   - Если списка нет — нажми **Show available providers** или подобную кнопку.
3. Нажми на **YooKassa**.

## Шаг 2.3. Привязать ЮKassa-магазин

@BotFather начнёт диалог с подключением:

1. **Войти на сайт ЮKassa** через @BotFather — он откроет ссылку. Залогинься теми же учётными данными, которыми сейчас пользуется наш магазин для сайта (`account_id` ЮKassa).
2. Подтверди привязку магазина к боту.
3. После успешной привязки @BotFather пришлёт **provider token** — это длинная строка, обычно вида:
   ```
   381764678:TEST:99999999     (тестовый токен)
   ```
   или:
   ```
   381764678:LIVE:99999999     (боевой токен)
   ```

> **Важно**: ЮKassa выдаёт **два разных токена** — тестовый (TEST) и боевой (LIVE). Нам нужен **LIVE-токен** для продакшна. Тестовый можешь приложить отдельно, если у тебя его попросит Игорь для отладки.

## Шаг 2.4. Сохранить токен

**Скопируй LIVE-токен и сохрани под названием `TELEGRAM_PAYMENT_PROVIDER_TOKEN`.**

⚠️ **Важно**: этот токен **секретный** (в отличие от Sentry DSN). Никогда не публикуй в общих чатах или коммитах. Передавай только в личке.

## Что-то пошло не так (Telegram Payments)

| Проблема | Решение |
|---|---|
| @BotFather не показывает кнопку **Payments** | Возможно ты в чате с другим ботом. Проверь, что выбрал правильный бот через `/mybots`. |
| В списке провайдеров нет YooKassa | Нажми **Show available providers**. Если всё равно нет — YooKassa может быть переименована в **ЮKassa** или **YooMoney**. |
| @BotFather говорит «магазин уже привязан к другому боту» | Спроси у Игоря — возможно токен уже был получен ранее. |
| Запутался какой токен — TEST или LIVE | Тот, в котором между двоеточиями написано `LIVE`, — это боевой. |
| Получил токен, но забыл скопировать | Отправь `/mybots` → выбери Symancy → **Payments** → **YooKassa** → @BotFather покажет токен снова. |

# Что прислать Игорю в итоге

В Telegram или email пришли **три строки** (формат именно такой):

```
VITE_SENTRY_DSN=https://...@o....ingest.sentry.io/...
SENTRY_DSN=https://...@o....ingest.sentry.io/...
TELEGRAM_PAYMENT_PROVIDER_TOKEN=381764678:LIVE:99999999
```

⚠️ **Внимание про секреты:**
- `VITE_SENTRY_DSN` и `SENTRY_DSN` — публичные ключи, можно публиковать.
- `TELEGRAM_PAYMENT_PROVIDER_TOKEN` — **секретный**, только в личку.

# Что будет после

Когда ты пришлёшь все три значения, Игорь:

1. Пропишет `SENTRY_DSN` и `TELEGRAM_PAYMENT_PROVIDER_TOKEN` в `/var/www/symancy-backend/shared/.env` на сервере
2. Перезапустит бот (`pm2 restart symancy-backend --update-env`)
3. Добавит `VITE_SENTRY_DSN` в GitHub Secrets
4. Запустит деплой фронтенда для применения `VITE_SENTRY_DSN`
5. Проверит работоспособность:
   - Тестовое сообщение об ошибке → должно прийти в Sentry
   - Команда `/buy` в боте → должна показывать кнопки «Картой YooKassa» и «Telegram Stars»
   - Тестовая оплата картой 100₽ через бот → кредит должен начислиться

С этого момента:
- Все ошибки сайта и бота видны в твоей Sentry-панели в реальном времени
- Пользователи могут оплачивать кредиты **картой ИЛИ Telegram Stars** прямо в боте, без перехода на сайт
